# Практическая работа 2 по РБПО

Анализ уязвимостей исходного кода Python, C++ и JavaScript и построение датасета
с корреляцией CWE/CVE. Основа — выданная методичка: VulnMart, C++-пример и
Express/SQLite-пример. Репозиторий содержит готовые решения, исходные протоколы,

добавлены 4 запуска C++, 2 статические проверки Python и 4 браузерных воспроизведения HTML.
Bandit, Cppcheck и ESLint запущены; их ограничения разобраны в отчётах.
CVE используются как аналоги. Модельные CVSS не выдаются за оценки локального стенда.

## Воспроизведение на Arch Linux

Команды выполняются из корня репозитория обычным пользователем. `sudo` нужен
только для установки системных пакетов. Скрипт pacman выполняет полное обновление
системы вместе с установкой зависимостей; запуск установки не требуется для сдачи
готовых файлов.

```bash
bash scripts/setup-arch.sh
bash scripts/run-all.sh
```

Системные зависимости: base-devel, git, python, python-pip, nodejs, npm, cppcheck,
iputils. Python ставится в `.venv`, JavaScript — в локальный `node_modules`.
`npm ci` использует поставляемый lock-файл; версия нативного sqlite3 может требовать
локальной компиляции и доступа к сети за заголовками Node.

Повторный запуск заменяет соответствующие файлы evidence. Если нужна сохранность
исходного протокола, сначала создайте отдельную рабочую копию. Python-тесты используют
временную БД. Node-тесты используют БД в памяти и свободные loopback-порты.

Запуск отдельных этапов после установки:

```bash
.venv/bin/python scripts/verify.py --only python
.venv/bin/python scripts/verify.py --only cpp
.venv/bin/python scripts/verify.py --only js
.venv/bin/python scripts/verify.py --only sast
.venv/bin/python scripts/build_dataset.py
```

## Ручной запуск приложений

VulnMart, в отдельном терминале из корня:

```bash
(cd projects/python/vulnmart && ../../../.venv/bin/python app.py)
```

Адрес: http://127.0.0.1:5055. Исправленная версия:

```bash
(cd projects/python/fixed && ../../../.venv/bin/python app.py)
```

Адрес: http://127.0.0.1:5056. Для обеих версий учебные данные:
admin/password123, sarah/sarah1995, devraj/devraj_2001. Эти пароли намеренно
сохранены для сравнения; никакие реальные учётные записи не используются.

JavaScript:

```bash
node projects/javascript/vulnerable.js
```

Адрес: http://127.0.0.1:3000/hello?name=Alice. Исправленный вариант
`node projects/javascript/fixed.js` слушает порт 3001.
У JS нет графической главной страницы `/`, входные точки — `/user`, `/hello`, `/ping`.
C++-программы собираются при `--only cpp` в игнорируемый каталог `build`.

## Доказательства и ограничения

Фактическая среда подготовки — Ubuntu 24.04, Python 3.12, Node 24.19.0, GCC 13.3.0,
Cppcheck 2.17.1. [Метаданные](reports/Шмеркович/evidence/environment.json).
Arch-скрипт подготовлен, но на Arch запуск не выполнялся. Скриншоты не имитировались.

Исходные HTTP-протоколы XSS дополнены воспроизведением их HTML в изолированном
браузере Edge: скрипт исполняется в уязвимых ответах и не исполняется в исправленных.
Это воспроизведение сохранённых ответов, а не повторный запуск всех серверов.
DAST выполнен целевыми HTTP-сценариями; отчёт ZAP не заявляется. В среде нет ping:
инъекция shell подтверждена встроенным printf, но нормальный ICMP в fixed не проверен.
LeakSanitizer отключён из-за ограничения /proc; ASan-проверки границ памяти включены.
Полный аудит зависимостей и production-hardening не входят в результат.

Уязвимые приложения запускать только локально на учебных данных. Встроенные
web-серверы привязаны к loopback. Исправленные варианты показывают конкретные меры
защиты, а не готовность к публичному развёртыванию.

## Дополнительная проверка от 17 сентября 2026 года

Новые протоколы получены на Windows, g++ 13.2.0 и Edge; точные версии и время
сохранены в evidence. Прежние 30 проверок относятся к Ubuntu и не перезаписаны.
Файлы null_pointer.cpp и null_pointer_fixed.cpp дополняют пункт 3.5 методички;
исходный vulnerable.cpp и снимок VulnMart сохранены без изменений.

```bash
python scripts/check_additions.py
# После setup-arch.sh; для другой ОС укажите путь своего браузера:
RBPO_BROWSER_PATH=/usr/bin/chromium node scripts/check_xss_browser.cjs
python scripts/build_dataset.py
python scripts/validate_delivery.py
```

Браузерный скрипт использует Playwright 1.62.1 из .browser-tools. setup-arch.sh
устанавливает его и Chromium. В Windows можно задать RBPO_BROWSER_PATH на msedge.exe.
RBPO_PLAYWRIGHT_MODULE позволяет указать другой установленный модуль Playwright.
Браузер блокирует внешние запросы и проверяет только сохранённые учебные HTML-ответы.

Не подключайте run-all.sh через точку: его `set -e` действует на вызывающую оболочку.

Python/JavaScript-синтаксис, ссылки и целостность датасетов. Приложения и браузер
